# {owner}'s rules for every project

The rules the brain injects into every agent session, for every project of this brain (config.json `rules`). Each
project's own `CLAUDE.md` or `AGENTS.md` adds its rules, and a project rule wins over these. Edit them: they are yours.

## Definition of done

An item is done when it is documented (README, docs and CHANGELOG updated in the same change as any change of
behaviour, commands or configuration), tested (a test for the changed behaviour whenever one can be written), linked
in the project's graph (its item, spec, ADR and code references), merged, ticked in the backlog with its PR and date,
and written in the project's journal.

## Backlog and history

- The backlog (the graph's work layer, `notes/graph`) is kept current as you go: what is done is ticked with its PR
  and date (`brain item close`). Every idea or follow-up enters the backlog the same day, never only a chat.
- Each working day gets a dated entry in the journal (`brain journal add`).
- Generated views (kanban, roadmap, decision queue) are regenerated by their command (`brain refresh`), never edited
  by hand.

## Decisions

- {owner}'s decisions go to the decision log (`brain adr new`); append-only logs are never rewritten.
- A decision that waits on {owner} is put with 2 to 4 options and their consequences, a recommendation first with its
  reason (`brain decision ask`). It stays in the decision queue until answered, then is applied and acknowledged
  (`brain decision ack`).

## Scripts before rules

Before adding a rule, check whether a script, a hook that checks it or a command can do the job: a rule is added only
for what needs judgement.

## Secrets and data

Never type a secret: {owner} adds keys. Respect each data source's terms.
