section: Added

- `brain views`: one writer of the generated views (`brain.views`, `docs/views.md`). Without a flag it lists the
  views git tracks (a `GENERATED by` marker in their first lines or a `_generated_` name, as the merge driver knows
  them), where the checkout stands, those changed or staged here and those the merge driver kept from one side
  (`--json`). On a branch, `--unstage` takes the staged views out of the index after `git add` (the working tree keeps
  them for the branch's checks) and `--reset` puts every view back at HEAD before a merge of the default branch.
  `--write`, in a worktree at the default branch's tip (refused in a main checkout), runs brain sync's writes, the
  audit view (`--no-audit`: not) and brain check, lists the files it changed and, with `--commit`, commits those alone;
  it refuses another engine than the pin unless `--force`. A branch that still commits its views keeps working: the
  merge driver's view kind stays the fallback. The scout (`brain audit --diff`) no longer asks a branch for a fresh
  `FEATURES.md` (its check `features.md` is `never` in the scout): the full audit and the default branch's check do
  (`wi-brain-views-one-writer`).
