section: Added

- `brain migrate --plan` / `--apply`: the engine's migrations of its own formats (the brain's `config.json` and this machine's truth-local files under `$BRAIN_HOME`): one registry of step functions per format and version, `brain.migrations`, which the readers use too (`brain.stateio.load` and `brain.config.load` run a file's pending steps in memory, so no command saves a file at a version its data does not have; a file no step reaches is behind, read-only); the plan read-only, the apply a backup of each file first, one atomic write per file (its integrity sidecar with it), each step logged in `$BRAIN_HOME/migrate/applied.jsonl` with its backup (a new engine store, `migrate`, class sealed); a file's own `v` says what is pending, so a second run applies nothing, and the first failure leaves its file as it was. A config.json with changes not committed, or whose git status cannot be read, is refused; an engine run from a source folder refuses `--apply` on the default home unless `--dev-engine`. `brain update` prints the migrations pending and applies none. No format has broken yet: the engine ships no step today (docs/formats.md, « Migrations »; `wi-brain-migrate`).
